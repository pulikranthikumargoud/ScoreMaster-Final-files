🎯 Why this is easier to maintain
Task	Before (Method 2)	Now (Method 3)
See how many images Q48 has	grep -o '<img' solution_field | wc -l	q.solution_images.length
Add a 4th image	Manual JSON edit, insert <img> block	python bake_solutions.py (drops in 48_4.png)
Remove an image	Manual JSON edit, delete <img> block	Delete 48_3.png → rerun script
Copy a solution to another Q	Copy giant HTML blob	Copy solution string + array items
Verify solution	Scroll through 116K chars	Read 3 array lines
Diff between shifts	Massive one-line change	Clean field-by-field diff
Corrupted solution image	Hard to isolate	Delete one array item
📋 Summary
Method 2	Method 3
bot.py patches	0	2 (~30 lines total)
JSON structure	<img> blob in one string	Clean text + array
Multi-image	✅ works	✅ works (cleaner)
Maintenance	Manual JSON surgery	Drop file → rerun script
Reparsing preserves solution	⚠️ No (regen from JSON loses nothing, but re-scrape loses it)	✅ Yes (survives re-scrape)
The last row is the key win. If you ever resubmit the RRB link (e.g. parser bug fix), extract_test_data() regenerates test_data from scratch — Method 2's <img> blob in solution is wiped. Method 3's solution_images field... also gets wiped by a fresh scrape.

Wait — that's true for both. Neither survives a fresh scrape from the RRB URL.

However: both survive /regen_from_json. That's the actual use case. And Method 3 is easier to maintain during that workflow because you can bulk-edit solutions across multiple shifts with simple scripts:

python
# Example: Add the same explanation text to all 7 Wiris formula Qs
for p in MASTER_JSON_DIR.rglob("*.json"):
    payload = json.loads(p.read_text())
    for q in payload["test_data"]:
        if q.get("original_qno") in ["12","25","27","35","48","69","72"]:
            q["solution"] = "See the formula in the question image."
    p.write_text(json.dumps(payload, ensure_ascii=False, indent=2))
That 6-line script would be a nightmare with Method 2 (regex surgery on HTML blobs). With Method 3, it's trivially safe.
